# 利用フィードバック

[共通規則](../../../../_control/rules.md)に従い、対象のタスクで下書きを作る。共有機構自体の改善は管理タスク、project内の観測整理はそのprojectのタスクで扱う。別のactiveを無断で切り替えない。

人が提供した事実と登録済み入力だけを使い、版・環境・発生条件・実行結果を推測で補わない。観測事実、原因の推定、改善提案を分ける。

## 複数の問題

1. 観測事実をWIPの`feedback_triage.md`へ重複なく並べ、影響、再現性、回避策、統合・分割理由、下書き候補／未提出の別を記す。
2. 同じ原因・変更対象・受入条件で完了判断できる問題だけをまとめる。件数削減だけを理由に混ぜない。
3. 影響と根拠から先に扱う候補を提案する。言及順や長さを重要度とみなさない。
4. 人が別途件数を指定しなければ、一度に作る下書きは最大3件。残りは一覧だけにする。分け方が不明なら一覧で判断を求める。

## 一件の下書き

件名、利用環境、実際に起きたこと、期待したこと、確認済みの発生条件、影響と回避策を記す。原因推定と改善提案は任意の別項目とする。未確認と「なし」を混同しない。

機密情報、個人情報、認証情報、非公開URL、顧客データを除き、人へレビューを依頼する。必要な具体例は公開可能な最小例へ置き換え、置換したことを明記する。

## 投稿

[投稿先](https://github.com/Keiichiro-Tsukamoto/project-directory-template/issues/new)への投稿は、人が公開内容・対象・件数を明示的に承認した後だけ行う。下書きの承認は投稿承認ではない。アクセス不能なら承認済みMarkdownを人へ渡し、投稿したとは報告しない。
