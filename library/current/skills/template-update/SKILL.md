# 共通機構の更新

[共通規則](../../../../_control/rules.md)で作業領域管理を選び、登録・切替手順に従って管理タスクを開始する。projectのタスクから依頼された場合も、共有部分の反映をそのprojectの操作として扱わない。

開始後、[運用ガイドの共通規則の更新](../../../../_control/reference/operation_guide.md#共通規則の更新)を管理タスクのcontextへ登録して読む。共通の承認・参照保護・完了処理をここへ複製しない。

## 更新元

- 人が別の更新元を指定しなければ、[既定更新元](../../../../_control/reference/external/github_project_directory_template_release.md)を管理タスクのcontextへ登録して使う。外部取得には[外部参照ガイド](../../../../_control/reference/external_resource_context.md)を登録して適用する。参照記述の欠落や取得不能を、別の取得先で補わない。
- 更新元の場所、確認できた版、参照する正確な相対パス、更新元を変更しない条件を、管理WIPの`wip/<Task ID>/template_update_source.md`へ記録してcontextへ登録する。取得実体内の文書はこの記録を介して読み、contextへ直接登録しない。
- 取得実体が必要なら管理WIPの`wip/<Task ID>/.tmp/template-source/`へ必要分だけ置く。`reference/external/`へ展開せず、外部の作業場所を前提にしない。保存と取得の許可を記録だけで代用しない。
- 更新元が作業領域版を配布しているかを確認する。旧単一project版しか取得できない場合は更新候補として適用せず、その事実を報告する。最新版であることだけを互換性の根拠にしない。対応版の所在を確認できなければ人へ確認する。

## 更新案

管理WIPへ「更新候補、変更対象、保持対象、競合、検証方法、ロールバック方法」の六項目と、更新元・既存版・候補の正確な対応パスを示す。

共通規則・ガイド・管理プログラム・共通機構用スキルだけを候補にし、ルートREADME、管理表、project定義、進行中タスク、依存表、業務成果物、個人資料、外部参照の識別情報、固有コードを上書きしない。配布元の初期化処理を既存環境へ追加しない。既存LICENSEを保持し、必要な由来表示だけを別候補にする。

元の版が不明な差分やローカル承認条項は競合として残す。更新元にないという理由だけで削除候補を作らない。全体コピーや更新元への移動はしない。

検証対象は各管理範囲の状態・参照、共通規則とガイドの整合、固有ファイルの保持、登録済み外部参照、利用できる既存試験とする。更新前の版の退避先と、更新対象だけを戻す方法を示す。実行していない確認は予定と明記する。

変更パスと競合を人へ提示し、反映承認までWIP案で止める。承認後もGit変更は別の権限として扱い、参照・依存・登録先を更新して再確認する。
