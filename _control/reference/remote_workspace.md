# リモート保存と交代引継ぎ

## 適用範囲

この手順は、承認した範囲をDrive正本として保存し、担当する環境を交代する場合に使う。ローカルだけの既存運用は変えない。current・reference・archive・library等は資料の役割を表し、遠隔という理由で役割や配置を変えない。自動同期、同時編集の調停、最後の正常な一式への自動復元は行わない。

識別・取得・鮮度・キャッシュ・外部書込みは[参照リソースの共通手順](external_resource_context.md)を使う。独自の索引・取得方式・タスク状態は追加しない。基本操作にPythonは必須でない。同じ保存先への書込み担当は一つとし、人が交代を宣言する。

## 保存先と資料の登録

作業領域管理タスクで、指定Driveフォルダの参照記述を既存の[_template.md](external/_template.md)に従って作り、`workspace:_control/reference/external/remote_workspace.md`へ置く。これは保存先の参照記述であり、本ガイドとは別ファイルである。schemaの項目・許容値は変えない。

対象オブジェクトには、どの下位範囲を保存しDrive正本とするか、何を含めないかを明記する。構造はdynamic-collection、構成単位はfile、構成規則は指定フォルダ以下の配置に従うものとし、取得モードはliveとする。構成員一覧の鮮度を確認できる指標がなければ、鮮度確認方法はrefetch、キャッシュ再利用は禁止とする。保存先全体の一覧と、個々の本文の鮮度確認は区別する。

保存先設定・正本切替・参照記述配置は対象と保存許可を示して承認を受ける。通常取得では、既に許可された同じ対象・操作の承認を繰り返さない。対象外の既存資料を勝手に移行しない。

Driveにも通常の相対配置と実際の名前を保つ。`_control/rules.md`は指定フォルダ直下の_control内に置き、管理表・タスク詳細・必要なガイドを含める。currentだけでなく必要なWIP・参照・旧版・素材も保存する。コード・スキル・library・profilesも既存の配置を維持し、取得しただけで実行・インストールしない。資格情報、.git、同期アプリ設定、不要なキャッシュを無条件に含めない。

個々の遠隔成果物は、役割に合うcurrent等へ同じ書式の参照記述を置き、contextへ登録する。例えばDriveの`projects/P-001/current/report.pdf`に対し、ローカルの`projects/P-001/current/report.remote.md`へその資料のID・対象・利用条件を記す。名前のremote部分は例で、特別な書式ではない。参照記述の先頭見出しとschemaは共通ひな型どおりとし、本文を装わない。参照記述自体も元の相対配置でDriveへ保存し、既存本文や参照先へ無断で上書きしない。全保存ファイル分の記述を一括生成せず、必要な資料に作る。

## 起動と再開

### ローカル入口のない初回

人が指定したDriveフォルダから、実際の`_control/rules.md`、本ガイド、共通参照ガイド、`_control/reference/external/remote_workspace.md`を取得して読む。入口が存在しなければ未設定として保存側へ確認し、似た名前や独自索引で代用しない。ここでは起動用の記述と規則を読むだけで、未選択の業務本文を使わない。

保存先の識別・境界・許可を確認し、起動に必要な共通管理表と、指定projectのproject.md・tasks.md・context.md・対象タスク詳細を元の配置で新しい空のローカル作業場所へ取得する。project未指定ならrulesが許すproject候補案内に必要な名前と定義だけを確認して選択を求める。他の管理表・本文を先読みしない。

人が必要な一式の取得も依頼している場合は、登録した集合の境界内でファイル名・種類を確認し、一式を元の配置で取得できる。これは全本文をLLMへ読む許可ではない。既存ローカルルートを上書きせず、領域外へのリンクをたどらない。Google純正形式を普通のローカルファイルとして取得できると仮定しない。

取得後は最新のローカルrulesを読み、この起動の接続は完了済みとして1節の対象選択へ進む。同じ入口取得を繰り返さない。対象タスクへ保存先の参照記述と必要なガイドを登録し、入力一覧は最新contextから得る。本文を使う前に、共通参照手順で参照記述と必要な版を確認する。

### 既存の作業場所

ローカルrulesから入り、保存先記述の識別子・境界と人の交代指示を確認する。送る側の保存完了を確認し、初回と同じ範囲の起動用管理情報を保存先から更新する。ローカルに唯一の未保存編集があれば、上書きせず両方を保持して扱いを確認する。取得後は更新後のrulesと管理表を読み直す。

対象タスク詳細のNotesで進捗・未解決事項・次の操作を確認し、最新contextの参照記述から必要な入力を得る。本文の再取得・キャッシュ再利用は共通参照手順に従う。Notesに第二の入力一覧を作らず、同名のローカルファイルの存在を最新版の根拠にしない。

### ローカルにない資料を探す

current・archive・library・reference等の資料がローカルにないことを、保存先にも存在しないという意味にしない。人から資料探索を依頼された時や、登録入力の取得先・再利用候補の確認が必要な時は、保存先記述が定める集合の実一覧を共通手順で確認する。タスクのNotesやcontextにない追加資料もここで確認できる。必要な下位階層だけをたどり、選んだ遠隔資料の正確な参照記述をcontextへ登録してから利用する。全階層の一覧・全本文を毎回読み込まず、未読資料の意味を名前だけから断定しない。

移動・削除の判断は、正確な対象と現在の所在を確認し、[参照保護](operation_guide.md#参照元の削除移動置換)と承認に従う。一覧から消えただけでローカル本文を削除しない。差分が不明なら未保存編集を保持したまま新しい場所への一式取得を提案する。

## 保存と交代

1. 対象の書込みを止め、未完了タスクのNotesに確認済み進捗・未解決事項・次の操作を残す。入力はcontextを原本とし、ファイル一覧を重複して持たない。未保存編集、保存失敗、承認済みの移動・削除等の例外は、その対象とともに記録する。
2. Notesを「準備中」として先に保存する。承認済み保存範囲の名前・種類と、書込みに必要な版を確認し、管理情報・確定成果物・必要な作業途中の資料を保存する。タスクのcontextにない完成成果物や共有資料も、設定範囲の保存対象から漏らさない。未変更資料は共通手順の条件を満たす場合に再送を省ける。
3. 対象ごとに場所・名前・実形式と必要な内容・参照を確認する。外部書込み前の版確認、未保存編集の保持、失敗時の停止は共通参照手順に従う。Google Docs・Sheets・Slidesは可能なら正本を直接編集し、Officeへ暗黙変換しない。書出しを使う場合は正本と区別する。
4. 必要範囲の保存確認後、Notesを「保存確認済み」にしてタスク詳細を最後に保存・確認し、人へ交代可能と報告する。完了済み作業だけを交代する場合は、共通の完了記録と保存確認の報告から再開し、新しい引継ぎ専用タスクを作らない。保存途中は交代しない。引継ぎだけを理由にタスクをdoneにしない。

## ローカル本文の整理

ローカル本文を消す前に、保存先で必要な内容・添付・素材を再利用できることを形式に応じて確認する。正確な対象を列挙して承認を得る。参照記述・パス・識別子等の小さな管理記録を残し、contextと必要な参照先を更新してから、保存済み作業用複製だけを整理する。起動に必要な規則、唯一の未保存編集、再取得不能な実体を消さない。

同期アプリでローカル削除がDriveへ伝播する場所を、単なる複製として消さない。削除不可なら残存場所を報告し、同じPC内への移動だけで撤去済みとはしない。保存確認とローカル整理完了は分ける。タスク詳細等の本文に機密がある場合も、小さな所在記録と混同して残存なしと報告しない。

## 能力不足・失敗時

取得能力・鮮度・保存許可・入力制限の不成立は共通参照手順に従う。接続結果がBase64等で会話にしか返らず、一式を通常ファイルとして取得できる方法が不明なら、人が用意するコピー等の代替を提示する。長文の手作業転記を既定にしない。元バイトの受渡しがないことだけで普通の読取りも不可とはしないが、読めたことを一式復元・安全な撤去の証明に広げない。

追加調査前に、不成立が利用者の必須条件か、自分で加えた保証かを区別する。満たせる別方式があれば案を更新し、必須要件自体を変える時だけ判断を求める。
