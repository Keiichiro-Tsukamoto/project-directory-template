# Gitと成果物の管理

Gitは必須ではない。[規則](../rules.md)の承認条件を優先する。

## 利用できる機能

Gitがなければ対象ファイルと管理表を手動で照合する。読取可能なら選択タスクの登録済みパスと管理表に限定して差分を確認する。領域全体の変更一覧・全ファイルハッシュを無条件に取得しない。

ハッシュ計算も任意である。同一性が受入条件なのに利用可能な方法で確認できなければ、その判断を止める。計算していない値を記録しない。

## 変更操作

branch、stage、commit、push、remote、履歴、.gitignoreの変更には対象と操作の承認が必要。既存の未関連変更を退避・破棄・登録しない。既存の運用方針を優先し、Gitが使えることを変更許可としない。

## 成果物一式

主成果物と、利用・保守・再現に必要なものを一式として配置する。採用判断だけの証跡はarchiveへ、一時物は承認範囲内で削除または隔離する。主ファイル、保守用資料、関連証跡の正確な場所だけを短く示す。Git履歴でWIP・現行・旧版の配置を代用しない。
