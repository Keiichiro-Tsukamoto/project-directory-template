# 外部リソース・コンテキストガイド

## 基本方針

外部リソース1件につき、原則として`reference/external/`へ参照記述ファイルを1件置きます。`context.md`には外部URLではなく、このローカルファイルを登録します。

リソースは、サービス、ワークスペース、リソース種別、リソースIDの組み合わせで識別します。表示名とURLは変更される可能性があるため、補助情報として扱います。

範囲の限定された集合を常に一緒に使う場合を除き、1件の参照記述で複数リソースを表現しません。ドライブ、サイト、フォルダ、ワークスペース全体を登録しません。

## 取得モード

### live

タスク開始時または再開時の最新版を取得します。鮮度を優先する情報に使用します。実際に確認したリビジョンと取得日時は一時状態へ記録し、検収や再現に必要な場合だけエビデンスへ昇格させます。

### pinned

`期待するリビジョン`と一致する版だけを取得します。指定版を取得または検証できない場合、最新版へ置き換えず作業を停止します。

### snapshot

ローカルの固定スナップショットを使用します。参照記述とスナップショットの両方を同じTask IDで`context.md`へ登録します。`ローカル保存`が`禁止`なら使用できず、`要承認`なら保存前に人の承認が必要です。

## 変更検出

次の順序で確認します。

1. サービスが提供するリビジョン、バージョン、ETag
2. サービスが提供する最終更新情報
3. 安定したエクスポート形式のコンテンツハッシュ
4. ローカルスナップショットのハッシュ

外部領域全体をハッシュしません。異なるエクスポート形式のハッシュを同一視しません。Git差分はローカルの参照記述とスナップショットを確認できますが、liveのリモート内容が不変であることは証明しません。

## 一時状態とエビデンス

リビジョン、ETag、取得日時、取得結果、エラー、任意のハッシュは`wip/T-XXX/.tmp/external-state/`へ置けます。この場所はGitとcontextの対象外です。

検収、再現、外部更新の証跡に必要な情報だけをWIPエビデンスへ移し、contextへ登録します。

## エラーと代替手段

アクセス不能またはリビジョン検証不能の場合、Web検索、類似文書、未登録キャッシュへ置き換えません。`代替手段: local-snapshot`が指定され、登録済みスナップショットがある場合だけ代替できます。古いスナップショットを使う場合は、その事実を明示します。

必要なコネクタがない環境では、コネクタへのアクセスまたは明示的に登録されたスナップショットを人へ依頼します。

## 外部更新

外部アクセスは読み取り専用が標準です。変更案は`wip/`で作成し、対象と操作について人の承認を得ます。書き込み直前にリビジョンを再確認し、変更されていた場合は上書きしません。反映後は新しいリビジョンと内容を確認します。

作業環境に編集権限がない場合、承認済み成果物を`current/`へ移して引き渡しタスクを完了し、リモート反映を別作業または別タスクにできます。リモート旧版とローカル承認版が食い違う場合、正とする版を人へ確認します。

## 保存と秘密情報

外部リソースを閲覧できても、ローカル保存またはGit登録が許可されているとは限りません。参照記述の各項目を確認し、`要承認`または不明なら人へ確認します。

アクセストークン、セッション情報、認証情報、有効期限付き署名URLその他の秘密情報を、参照記述、スナップショット、管理ファイル、成果物、ログ、Gitへ保存しません。

## 静的検証の限界

`validate_template.py`は、contextへ登録された参照記述の構造、値、スナップショット登録などを検査します。外部サービスへの接続、実際の権限、リモート版の一致、Git追跡状態は実行時または人による確認が必要です。
